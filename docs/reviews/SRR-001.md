## 3. Findings and dispositions

| # | Finding | Disposition |
| --- | --- | --- |
| 3.1 | `TG014-dal-a-single-method` raised on the DAL B low-level requirements: each is covered by exactly one unit test. | **Waived.** Each LLR is additionally exercised through the closed-loop and envelope-sweep integration cases attached to its parent HLR (`test_closed_loop_convergence`, `test_envelope_never_exceeded`, `test_integral_bounded`). Duplicating a second annotation on every LLR would add trace noise without adding verification value. Waiver recorded in `traceguard.toml` referencing this record. Approved by Software QA. |
| 3.2 | `HLR-ALTH-030` (bound the integral term) is verified by `method=analysis` demonstrated through a long saturated run rather than a formal proof. | **Accepted.** The bound asserted in `test_integral_bounded` follows directly from the anti-windup logic in `LLR-ALTH-031`, which has its own unit case. A formal argument is recorded in the design description; no additional case required at DAL B. |

## 4. Observations (no action required)

1. `SYS-ALTH-001` states the accuracy is "defined by the system requirements"
   without restating the number. This is intentional - the numeric tolerance
   belongs in the system specification - but reviewers should note that the
   closed-loop case `test_closed_loop_convergence` asserts a specific 5 m
   tolerance which must be kept consistent with the system specification if that
   number changes.
2. The example verification suite uses a minimal in-repository harness
   (`tests/unity_min.h`). On a real programme this would be replaced by the
   project's qualified test framework; no test body would need to change.

## 5. Conclusion

The trace data for the ALTH function is complete and bidirectional across
associations 1 to 4 of DO-178C 11.21. Associations 5 and 6 (test cases to test
procedures, test procedures to test results) are outside the scope of this record
and are covered by the Software Verification Plan.

One waiver is open (3.1). It is scoped to a single rule and is to be re-reviewed at
the next release audit.

**Disposition: closed, with one open waiver.**
